# code-scrape 改造方案：核心代码清单生成 + 源码汇总脚本化（去 UI、行数统计重写）

> 状态：**方案定稿、D1–D13 已全部裁定；实施中（P0 备份 ✅ ／ P1 语言表 + 词法统计 + 测试 ✅ ／ P2 清单生成 ✅）**
> 日期：2026-10-12（同日完成评审、自查修复与决策裁定）
> 改造范围：`code-scrape/` 目录内文件 + `project-critical/SKILL.md` 一行指针（D7 已授权）
> 需求来源：① 先生成核心代码清单 ② 用脚本把清单里的程序汇总成 md ③ 不再需要独立 UI ④ 行数统计要准确并覆盖更多语言

---

## 0. 结论速览

1. **清单生成要进工具内部**：目前 `核心代码名称.md` 靠人工/AI 按 `project-critical` skill 规则手工产出，工具只负责读它。改造后由脚本按 skill 规则直接生成，规则代码化、可复跑、可 diff。
2. **汇总环节脚本化、去 UI，且以"当前项目"为准**：删除 Tkinter 界面（`app.py` 1350 行 + `main.py` 的 DPI 启动逻辑），改为子命令式 CLI。**在项目根目录直接执行即可，不需要手动传路径、不需要勾选项目**——默认以当前工作目录为项目根，自动定位/生成清单、自动输出到项目的 `out/`，一条命令完成"生成清单 → 按清单汇总 md"，可无人值守在流水线里跑；项目名默认取目录名，与登记全称不一致时用 `--project-name` 校正（见 D10）。
3. **汇总产物只留源码正文，统计改到会话里输出**：`out/源代码-{项目名}.md` 不再写"软件著作权源代码文档"标题、不再写统计列表、不再有 `---` 分隔行，文档内容就是按清单顺序连续拼接的源码正文；项目名称/文件总数/物理行/空行/注释行/有效代码行等统计，改为**生成完成后打印到会话（控制台）**，需要落盘时用 `--stats-json`（如需旧头部，`--keep-header` 可临时恢复，默认关）。
4. **行数统计必须重写，现有实现不可信**：`processor.py:85-194` 的手写状态机在真实项目上同时存在**少算**与**多算**。实测样例：`config/WebConfig.java` 严格有效代码 47 行，现状只算出 26 行（少算 45%）；14 个 `.wxml` 的 37 行 HTML 注释被当成代码（多算）；汇总层面两向偏差互相抵消，得出"看起来合理"的 3304。
5. **重写方向**：语言定义表 + 单遍词法状态机（字符串内不误判注释、支持嵌套块注释/多行字符串/heredoc/SFC 分块），输出**物理行 / 空行 / 注释行 / 有效代码行**四口径，并强制恒等式 `物理 = 空行 + 注释 + 有效代码` 自检；语言覆盖从 7 组扩到 40+ 扩展名。
6. **风险前置**：`code-scrape/` **不在任何 git 仓库内**，删除 GUI 不可回滚。实施第 0 步先整体备份，再动代码。

### 1.2 现有流程（as-is）

```
选择源码目录 → 扫描（忽略规则过滤，无扩展名白名单）
  → 树形列表勾选（可"输入选中"：预填 核心代码名称.md 的路径清单并按清单顺序勾选）
  → 开始整理（逐文件读取 → 编码识别 → 统一换行 → 压缩空行 → 清行尾空白）
  → 组装 Markdown（头部：项目名/文件总数/代码总行数）

```

> **改造后（to-be）**：在项目根目录执行一条命令（零参数），自动扫描 → 自动生成清单 → 按清单自动汇总 → 写出 `out/源代码-{项目名}.md`（**仅源码正文，无头部统计**）→ 统计摘要打印到会话。

## 2. 问题清单（带证据）

### 2.1 清单生成不在工具内（需求 ① 的缺口）

- 每个项目都要重新让 AI 走一遍 skill 流程，规则执行结果不可复现、不可 diff，易出现漏项（历史上出现过 `backend/src/stats/` 三文件漏列）或把样式/配置/空包误入清单。
- 工具侧只做了"读清单"，没有"校验清单"能力：清单里路径不存在、指向 `.wxss`/`.json` 这类应剔除文件时，工具静默跳过（`app.py:790 _match_entries` 未命中即忽略），错误被吞掉。

### 2.2 GUI 与批处理耦合（需求 ③ 的缺口）

- 必须人工点选：扫描 → 勾选 → 开始整理 → 保存，无法在流水线（说明书排版 `payout`、一致性审查 `project-review`、批量重生成材料）中调用。
- 打包成 `console=False` 的窗口程序（`软著源码整理工具.spec:32`），无法在无桌面环境、远程会话或脚本中运行。
- 界面态与业务逻辑混写（`app.py` 中清洗/统计/保存逻辑与控件强耦合），无法单测。
- 每次使用都要"选路径 → 扫目录 → 勾选项目"（`app.py:988 _browse_folder`、`app.py:1052 _start_scan`），没有"以当前项目为准"的零参数用法；同一个项目重复出材料时，路径与勾选状态靠人工维持，易跑错项目。

### 2.3 行数统计不准确（需求 ④ 的核心，重点）

现状实现：`processor.py:85-194 count_code_lines()`，手写行级状态机，只有 7 组扩展名分支。

#### 证据 A：缺陷复现（直接调用现有函数）

| 用例 | 输入要点 | 严格应为 | 现状结果 | 结论 |
|---|---|---|---|---|
| Java 字符串含 `/*` | `String sql = "/* hint";` 后续 2 行代码 | 3 | **1** | 字符串里的 `/*` 被当成块注释开始，**吞掉文件后续所有行** |
| `.wxml` 含 HTML 注释 | `<view>` + `<!-- 注释 -->` + `<view>` | 2 | **3** | `.wxml` 无规则分支，注释行被计为代码 |
| `.vue` 内 `<script>` 注释 | `// 注释` 在 `<script>` 内 | 注释 | **计为代码** | `.vue` 只认 `<!-- -->`，不认 JS 行注释 |
| `.sql` 行注释 | `-- 整行注释` | 注释 | **计为代码** | `.sql` 只配了 `//`，不认 `--` |

#### 证据 B：真实项目对照（70 文件清单，同口径清洗后）

| 语言 | 文件数 | 物理行 | 严格有效代码行 | 现状统计 | 偏差 |
|---|---|---|---|---|---|
| `.java` | 35 | 1335 | 1289 | 1262 | 少算 27 |
| `.js` | 21 | 1413 | 1337 | 1360 | 多算 23 |
| `.wxml` | 14 | 682 | 645 | 682 | 多算 37 |
| **合计** | **70** | **3430** | **3271** | **3304** | 净差 33（两向偏差抵消） |

> 严格值由一次性原型校验器测得；该原型后来被查出自身有 103 处双向误判（见附录 6），**已弃用为基线**。本表仅用于说明"现状算法缺陷的量级与方向"：**最终实现（P1/P3 实测）为有效代码 3288**（见 §10 AC4 与附录 9）。

单文件级别的错误更触目：

| 文件 | 严格有效 | 现状 | 说明 |
|---|---|---|---|
| `backend/.../config/WebConfig.java` | 47 | **26** | 第 38 行 `registry.addMapping("/**")` 的 `/**` 在**字符串内**，被误判为块注释开始且无 `*/` 收尾 → 此后所有行被吞 |
| `pages/project-detail/project-detail.wxml` | 78 | 86 | 8 行 HTML 注释被计为代码 |
| `pages/login/login.js` | 79 | 86 | 7 行注释未识别 |
| `pages/preview/preview.js` | 108 | 100 | 8 行少算（`/**` 通配在字符串内） |

#### 证据 C：根因定位（`processor.py`）

| 行号 | 缺陷 |
|---|---|
| 92-111 | 语言分支只覆盖 7 组扩展名；`.wxml`/`.lua`/`.sql`(`--`)/`.rb`(`=begin`)/`.vb`(`Rem`)/`.hs`/`.erl`/`.pl` 等无规则或规则错误 |
| 172 | `if multi_start and multi_start in s` —— 只看子串是否存在，**不区分是否处于字符串/字面量内**，这是 `/**` 吞噬与 `"/*"` 误判的根因 |
| 134-164 | Python 三引号分支逻辑缠绕：`SQL = """..."""` 的赋值多行字符串被整块当注释；`"""` 与 `'''` 混用、同行开闭、转义引号均未正确处理 |
| 108-109 / 106-107 | `.vue` 只按 HTML 注释处理，`<script>` 区块内 JS 注释全部漏算；`.wxml` 落默认分支全算代码 |
| 167-169 | 单行注释只判 `s.startswith(prefix)`，不支持"注释符前有缩进以外内容"以外的语种差异（如 SQL `--`、Ruby `#` 与 `=begin`、Lua `--[[ ]]`） |
| 208-213 | `total_lines`（物理行）算了但**从未输出**；输出只有单一"代码总行数"，无空行/注释行口径，无法复核 |
| 全函数 | 无嵌套块注释（Rust/Swift/Kotlin）、无多行字符串（C# `"""`、JS 模板串、Lua `[[ ]]`、heredoc）、无 JS 正则字面量处理、无 SFC 分块、无未闭合容错 |

#### 结论

现状统计**每个文件的数字都不可信**，只是"少算"与"多算"在汇总时互相掩盖。而软著材料的实际用途恰恰是逐文件/逐页判断（60 页 ≈ 3000 行的页数换算），因此必须重写而非修补。

### 2.4 其它工程问题

- **无测试**：无任何用例，统计值改动无人能验证（本次对照全靠临时脚本）。
- **无版本控制**：`code-scrape/` 不在 git 仓库内，删除/重命名不可回滚。
- **目录不洁**：`debug.log`（无关的输入法日志）、`拿捏源码.png`（15MB）、`源代码-.docx`、`__pycache__/`、`build/`、`dist/` 混在源码目录里。
- **依赖可选**：`processor.py:30` 尝试 `chardet`，缺失时静默降级（目前靠 UTF-8 → GBK → latin-1 兜底）。

```
# 在项目根目录（当前工作目录）下直接执行，不需要任何路径参数、不需要选择项目
python <skill>/codescrape.py run
   │
   ├─(0) root = 当前工作目录 cwd；项目名 = cwd 目录名（仅保留中文）

   └─(8) report: **生成完成后把统计摘要输出到会话**（+ 可选 --stats-json 落盘）
```

## 6. 设计二：脚本汇总（`cli.py` + `reader/cleaner/markdown`）

### 6.1 调用约定（skill 使用方式，**以当前项目为准**）

- **不需要手动选择路径、不需要选择项目**：脚本在哪个目录被执行，哪个目录就是项目根（`cwd`）。在项目根直接执行 `python <skill>/codescrape.py run` 即可。
- 输出与清单自动落到当前项目：`<cwd>/out/核心代码名称.md` 与 `<cwd>/out/源代码-{项目名}.md`。清单的"存在则读取、不存在则生成"是 `run`（与 `pack --auto-list`）的行为；单独执行 `pack` 时清单必须已存在，否则报错退出 1（见 6.2）。
- 项目名自动取 `cwd` 目录名（仅保留中文，无中文兜底"项目"）；**目录名与登记全称不一致时（如目录"…系统"、登记"…小程序"），用 `--project-name "登记全称"` 显式校正**——文件名会进申报材料，名称口径是审查红线（新增决策点 D10）。`--project-name` 传入的名称**原样使用**（只做 Windows 文件名非法字符清洗），不再二次提取中文，避免把登记全称里的数字/版本号削掉。
- 忽略规则文件解析顺序：`--rules` 显式指定 > `<cwd>/忽略规则.gitignore`（项目自备）；都不存在则按"无规则"处理，**任何情况下都不创建文件**（P7 已删除脚本目录的默认规则文件，回退链随之取消）。
- `-r/--root` 仅保留给"一次处理多个项目"的批处理场景，日常使用不传。
- 判定失败时**不猜**：若 `cwd` 下既无源码文件也无清单，直接报错退出（退出码 1），不静默产出空文档。

### 6.2 子命令与参数

```
# 常规用法：在项目根目录下直接跑，零参数
python <skill>/codescrape.py run

子命令：
  run     默认：生成清单 + 按清单汇总（= list + pack）
  list    仅生成/更新 out/核心代码名称.md
  pack    仅按清单汇总（默认要求清单已存在；--auto-list 允许缺失时先生成）
  stat    只统计不产出文档（会话输出 + --stats-json）
  scan    诊断：列出扫描命中/被忽略文件与剪枝目录

公共参数（均为可选，默认值即"当前项目"）：
  -r, --root DIR           项目根；默认当前工作目录，skill 使用时不传（仅批处理覆盖）
      --project-name NAME  项目名；默认取 cwd 目录名（仅保留中文），目录名≠登记全称时必须显式传（D10）
  -l, --list FILE          清单路径；默认自动查找 <root>/out/核心代码名称.md
  -o, --out FILE           汇总 md 输出；默认 <root>/out/源代码-{项目名}.md（兼容 settings.json 模板）
      --rules FILE         忽略规则文件；默认 <root>/忽略规则.gitignore（无则按无规则处理）
  -k, --max-empty-lines N  空行压缩 0/1/2（默认取 settings.json，当前为 0）
      --with-file-headers  每份源码前插入路径分隔注释（默认关，见 D3）
      --keep-header        在 md 顶部写回旧版"标题 + 统计列表"（默认关；统计照常输出去会话）
      --stats-json FILE    把统计 JSON 落盘（会话输出不受影响）
      --strict             清单缺失/违规条目 → 退出码 2
      --allow-partial      读取失败不判失败
      --auto-list          （仅 pack/stat）清单不存在时自动先生成
      --legacy-report      汇总统计旁并列"旧版算法数字 + 逐条差异解释"（不复刻旧 bug 做计数，见 D8）
  -q, --quiet / -v, --verbose / --dry-run
```

补充约定：

- `pack` 默认要求清单已存在（不存在退出 1），`--auto-list` 打开后才允许先生成；`run` 恒为自动生成。`stat` 与 `pack` 同样需要清单，`--auto-list` 语义一致。
- `run --dry-run` 时清单不落盘，但会把内存中的生成结果直接交给汇总步骤（不因"清单不存在"报错），用于纯预览。
- 汇总 md 与清单均以 **UTF-8 无 BOM** 写出；`settings.json` 的 `output_dir` 为空时输出到项目根（沿用 GUI 旧行为），非空则相对 `<root>` 解析。汇总 md **以换行符结尾**（旧产物末尾无换行，仅此一处字节差异，行内容完全一致）。
- `--list`/`--out`/`--stats-json` 传相对路径时按项目根解析（不是按当前 shell 目录），保证 `-r` 批处理场景行为可预期。

### 6.3 退出码与日志

| 退出码 | 含义 |
|---|---|
| 0 | 成功 |
| 1 | 参数/环境错误（当前项目下无源码也无清单、输出不可写、`--root` 指向的目录不存在） |
| 2 | 清单校验失败（条目不存在、类型违规、小程序 `.wxml` 缺失）且启用了 `--strict` |
| 3 | 存在文件读取/解码失败且未加 `--allow-partial` |

退出码与"是否产出"的关系（P3 定稿）：

- 退出 2（`--strict`）：**不产出汇总 md**，避免清单本身不可信时生成不完整材料（缺失/违规条目与小程序成对问题直接列到 stderr）。
- 退出 3（读取失败）：**照常产出** md，失败文件以 `[文件读取失败：<路径>]` 占位行计入对账，报告与 `--stats-json` 给出失败清单；加 `--allow-partial` 则退出码归 0。
- 非 `--strict` 下的"清单条目不存在/类型违规"：告警并跳过该条，不进入正文（对账恒等式仍成立，`listing.missing`/`invalid` 给出明细）。

日志统一 `[级别] 消息` 前缀（沿用现有 GUI 文案风格，便于对照历史输出），错误写 stderr。

**控制台编码（P3 修正原条款）**：不强制改写为 UTF-8 —— 在代码页非 65001 的中文 Windows 控制台上，强制 UTF-8 输出反而乱码。改为**保留控制台自身编码、统一 `errors="replace"`**；仅当 `stream.encoding` 缺失或为 ASCII 时才切到 UTF-8。这样 GBK 控制台与 UTF-8 终端都能正确显示中文，个别无法编码的字符降级为 `?` 而不抛异常。

### 6.4 读取与清洗（沿用现有行为）

- 编码候选链：UTF-8 BOM（`utf-8-sig`）/ UTF-16 BOM → UTF-8 → GB18030 → GBK → Big5 → latin-1 兜底（去 `chardet` 依赖，保持零依赖）；记录每个文件的最终编码，走 latin-1 兜底时给出"可能乱码"告警。
- 换行归一：`\r\n`、`\r` → `\n`。
- 空行压缩：按 `max_empty_lines`（0/1/2），文件首尾空行不计（与 V1.5/V1.6 行为一致）。
- 行尾空白清理：仅去行尾，**保留行首缩进**。
- 大文件：超过 `max_file_size_mb`（默认 50）告警但不中断；读取策略为**一次读入 + 单次解码**（不在多个候选编码上重复解码，避免整文件驻留多份副本），另设 **256 MB 硬上限**防御异常文件（超过则判为读取失败并计入占位行）。

### 6.5 输出文档与统计输出（**文档只含源码正文**）

**md 文档内容（默认）**：只有按清单顺序连续拼接的源码正文，不含任何标题、统计列表或 `---` 分隔行。

```markdown
<按清单顺序连续拼接的源码正文，第一行即第一份源码的第 1 行>
```

- 不再写入 `# 软件著作权源代码文档` 标题、`项目名称/文件总数/代码总行数` 统计列表，以及其后的 `---`（用户 2026-10-12 明确要求：这段文字改为生成完成后输出到会话）。
- 保留 `--keep-header` 开关：确需旧版头部时可临时恢复（默认关）。
- 文件名分隔改为可选 `--with-file-headers`（默认关）；开启时按**语言表**生成注释前缀（`//`、`#`、`<!-- -->` 等，未知语言用 `#`）插入 `路径` 行，插入行**不计入**行数统计（对账恒等式里单列）。
- 读取失败的文件：正文插入 `[文件读取失败：<路径>]` 占位，失败清单在会话输出与 `--stats-json` 中给出。

**统计输出（生成完成后打印到会话）**，形如：

```
[完成] 项目：某水电验收项目　根目录：<项目根>
[清单] out/核心代码名称.md　条目 70　命中 70　缺失 0　违规 0（后端 35 / 前端 35）
[统计] 文件 70　物理行 3430　空行 0　注释行 142　有效代码行 3288　≈ 68.6 页（按正文 3430 行 / 50 行每页）
[语言] .js 21 文件 1413 行；.java 35 文件 1335 行；.wxml 14 文件 682 行
[输出] out/源代码-某水电验收项目.md（仅源码正文，无头部）
[提示] 跳过/失败：无
```

> 上例为 **P3 实测原样输出**（2026-10-12，水电项目 70 文件）：`[统计]` 与 `[语言]` 的数字同源，`[语言]` 按**物理行**降序、逐项之和等于物理行总数（1413 + 1335 + 682 = 3430）；`[语言]` 种类多于 8 种时其余合并为"其它 N 文件 M 行"。

- `--quiet` 只保留 `[输出]` 与错误行；`-v` 追加逐文件明细。
- `--stats-json FILE` 把同一份统计落盘（schema `codescrape/stats@1`），供审查/流水线引用。
- 统计不再进入 md，文档因此天然可复现（无时间戳差异）。

**统计输入与对账（防"统计数字与产物对不上"）**：

- 统计对象 = **清洗后、即将写入 md 的同一文本**（换行归一 + 空行压缩 + 行尾清理之后）。因此"有效代码行"会随 `max_empty_lines` 变化：`0`（默认，删全部空行）时 `blank = 0`，与既有汇编口径完全一致；`1/2` 时 `blank > 0` 属预期。逐文件 `code` 数不受空行压缩影响（只与注释判定有关）。
- 对账恒等式（每次运行输出前自检）：**md 正文总行数 = Σ各文件 phys + 失败占位行数 +（`--with-file-headers` 时）分隔行数**；`--stats-json` 里给出两侧数字，不等即内部错误。
- 页数估算基数 = **md 正文总行数**（即送排版的全部行），不是有效代码行数。
- `--legacy-report` 的"旧数字"由内置旧算法**快照**（`legacy_count.py`，即原 `count_code_lines` 原样搬移）一次性算出，仅作对照展示与差异归因；**正式产出的四口径与 md 一律走新实现**，不提供旧口径计数开关（D8 已定稿）。

**`--stats-json` 字段清单（schema `codescrape/stats@1`）**：

```
schema, generated_at            版本与生成时间（仅 JSON 里有时间，md 无）
root, project_name, project_name_source   项目根/项目名/名称来源（cwd 目录名 或 --project-name）
listing  { path, entries, matched, missing[], invalid[], backend, frontend }
totals   { files, phys, blank, comment, code, md_lines, pages }
md       { path, header_lines, body_lines }    正文行数与对账基数
by_language[] { ext, files, phys, blank, comment, code }
files[]  { path, ext, encoding, phys, blank, comment, code }
fallback_extensions[]            走通用兜底规则的扩展名
reconcile { md_body_lines, sum_file_phys, placeholder_lines, separator_lines, ok }
warnings[]                       未闭合注释/字符串、大文件、编码降级等
```

## 7. 设计三：行数统计重写（`loc.py` + `languages.py`）★核心

### 7.1 统计口径（先定口径，再定算法）

| 指标 | 定义 |
|---|---|
| 物理行 `phys` | 换行归一后的行数；无末尾换行的最后一行计入 |
| 空行 `blank` | `strip()` 后为空的行 |
| 注释行 `comment` | 该行**不含任何有效代码字符**，只含注释内容或落在多行注释/多行字符串内部 |
| 有效代码行 `code` | 含至少一个有效代码字符的行（**混合行计代码**，如 `int a = 1; // 说明`） |
| 恒等式 | `phys = blank + comment + code`（逐文件校验，不成立即内部错误） |

口径决策（见 D5）：

- **多行字符串内容行计注释**（Python docstring 是"文档"，软著审查看作注释）。
- **Shebang 行与编码声明行计注释**（`#!/usr/bin/env python`、`# -*- coding: utf-8 -*-`）。
- **混合行计代码行**（与主流工具 `cloc`/`tokei` 的"代码优先"一致）。
- 同时输出 `pages`（按 50 行/页估算），便于判断是否满足 60 页 ≈ 3000 行的材料需求。
- **与既有做法同源（可互相验证）**：此前乾图招聘项目的汇编口径即"有效代码行 = 正文行数 − 纯注释行"（正文已删空行），等价于本方案在 `blank = 0` 时的 `phys = comment + code`；本方案的四口径是它的超集，可用于复核历史数字。

### 7.2 语言定义表（40+ 扩展名）

`languages.py` 用不可变 `LangSpec` 描述每种语言：

```python
@dataclass(frozen=True)
class BlockComment:
    start: str; end: str; nestable: bool = False

@dataclass(frozen=True)
class LangSpec:
    name: str
    line_comments: tuple[str, ...] = ()        # 行注释标记
    block_comments: tuple[BlockComment, ...] = ()
    strings: tuple[tuple[str, str], ...] = ()   # (定界符, 定界符)，可多字符/多行
    escape: str | None = "\\"
    raw_prefixes: tuple[str, ...] = ()          # r/R/@/$@/f/@"/R"(...)" 等
    embedded: tuple[str, ...] = ()              # 宿主内嵌区块 (script/style/template)
```

覆盖分组（扩展名 → 语言）：

| 分组 | 语言与注释规则 |
|---|---|
| C 系 | `.c/.h/.cpp/.hpp/.cc/.cxx`、`.java`、`.cs`、`.js/.mjs/.cjs/.jsx`、`.ts/.tsx`、`.go`、`.rs`（嵌套块注释）、`.kt/.kts`（嵌套）、`.swift`（嵌套）、`.dart`、`.php`、`.scala`、`.groovy`、`.m/.mm` — `//` + `/* */` |
| 脚本 | `.py/.pyw`（`#` + 三引号）、`.rb`（`#` + `=begin/=end`）、`.sh/.bash/.zsh`（`#` + heredoc）、`.ps1`（`#` + `<# #>`）、`.bat/.cmd`（`REM`/`::`）、`.pl/.pm`（`#` + POD）、`.lua`（`--` + `--[[ ]]`）、`.r`（`#`） |
| .NET/VB | `.vb`（`'` + `REM`）、`.fs`（`//` + `(* *)`） |
| 函数式 | `.hs`（`--` + `{- -}` 嵌套）、`.erl`（`%`）、`.ex/.exs`（`#`，Elixir 用 `#` 不是 `%`）、`.clj`（`;`）、`.elm`（`--` + `{- -}`） |
| 标记/前端 | `.html/.htm/.xml/.svg/.wxml/.axml`（`<!-- -->`）、`.vue/.svelte/.astro`（SFC 分块）、`.jsp/.asp/.ejs/.hbs` |
| 样式 | `.css/.scss/.less/.styl`（`/* */` + `//`） |
| 数据库/配置 | `.sql`（`--` + `/* */`）、`.yaml/.yml`（`#`）、`.toml`（`#`）、`.ini/.conf/.properties`（`#`/`;`）、`.json/.jsonc`（`//` + `/* */`） |
| 其它 | `.pas`（`//`/`{ }`/`(* *)`）、`.f90`（`!`）、`.nim`（`#` + `#[ ]#`） |

> `.m` 有双语义：默认按 **Objective-C**（`//` + `/* */`）处理；若首行特征命中 MATLAB（`%` 注释、`function`/`end` 结构）切换为 MATLAB 规则并在报告标注。清单默认不收录样式与配置，但 `pack`/`stat` 可能收到手工清单，故语言表按"尽量全"设计；未识别扩展名走**通用兜底规则**（`//`/`#`/`--` + `/* */` + `<!-- -->`），并在报告中标注"兜底规则"。

### 7.3 词法状态机

单遍逐字符扫描，状态：`CODE / LINE_COMMENT / BLOCK_COMMENT(depth) / STRING(delim, raw)`。

**只在 `CODE` 状态识别注释与字符串起始** —— 这一条即修复现状最严重的 `"/*"`/`"/**"` 吞噬问题。

处理规则清单：

1. **字符串优先于注释**：进入字符串后，`//`、`/*`、`--`、`#` 全部视为普通字符。
2. **转义**：`\x` 跳过两字符；raw 前缀（`r"..."`、`@"..."`、`R"(...)"`）不处理转义。
3. **多行字符串**：Python `"""`/`'''`、JS/TS 模板字面量 `` ` ``、C# `"""`、Java 15 `"""`、Kotlin/Scala `"""`、Lua `[[ ]]`、Ruby `<<~HEREDOC`、Shell `<<EOF`、PHP heredoc —— 跨行时其内部行计注释（口径见 7.1）。
4. **嵌套块注释**：Rust/Swift/Kotlin/Nim/Haskell `{- -}` 支持嵌套，用深度计数；C 系不嵌套（保持语言真实语义）。
5. **SFC 分块**（`.vue`/`.svelte`/`.astro`）：扫描到 `<script>` 切换为 JS/TS 规则、`<template>` 用 HTML 规则、`<style>` 按 CSS 规则照实统计（独立样式文件不进清单，但 SFC 内的样式块行数照实计入，不搞特殊豁免）；`<script>` 内 `//` 与 `/* */` 正确统计。
6. **JS/TS 正则字面量 vs 除法**：启发式 —— `/` 前一个有效 token 属于"表达式结束符"（标识符、`)`、`]`、数字、字符串）时视为除法，否则尝试匹配正则（`/.../flags`），匹配失败则回退为除法。
7. **未闭合容错**：文件在字符串/块注释中结束时，正常收尾并记 warning，绝不抛异常、绝不吞掉整份文件。
8. **BOM/CRLF/Tab**：读取阶段已归一；行首缩进不影响分类。
9. **空文件 / 纯注释文件**：`code = 0`，合法。
10. **混合行**：`code(); // 注释` 计代码行；`/* 注释 */ code();` 计代码行；`/* 注释 */` 计注释行。
