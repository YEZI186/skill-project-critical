# 软著源码提取与格式整理工具 版本更新说明

**软件名称**：软著源码提取与格式整理工具
**用途**：扫描代码文件 → 格式清洗 → 生成 Markdown 源代码文档，用于软件著作权申请材料整理

## V2.0.3（2026-10-13）

**修复 V2.0.2 经独立对抗性复核暴露的 5 项缺陷**（复核结论：V2.0.2「不通过」）

- **【严重】`[交付]` 对账不平时误报"齐备"**：原判定只看文件是否存在，与 Step 5 完成判据（对账恒等式成立）口径冲突——实测同一份输出里先出「两份材料齐备」、再出「对账不平」。新增 `report.delivery_line()` 作为交付判定**单一真相来源**，三态化：`齐备` / `存疑`（已落盘但对账不平，明示"不得交付，先排查"）/ `不完整`（缺文件）
- **【严重】`[交付] 不完整` 是死代码**：原内联分支在 CLI 路径下不可达（清单缺失必先被 `CliError` 拦截）。改由 `delivery_line()` 独立承担，并补齐**清单缺失 / 汇总缺失 / 对账不平**三个负向分支的单元测试（`test_pipeline.py::DeliveryLineTest`）
- **【严重】完成判据在 `-q` 下不可满足**：SKILL.md 原判据要求会话出现 `[统计]` 行，但 `report.py` 的 quiet 早退不输出该行，照判据执行会陷入无意义返工。现 quiet 分支也输出 `[交付]` 行，判据改为「出现 `[交付] 两份材料齐备`」——`-q` 下同样可判定完成
- **【中】空项目场景三重冲突**：SKILL.md 原「出空清单模板」+「Step 5 强制」+「手工兜底」与脚本 exit 1 且无提示互斥。现 SKILL.md 明确**空项目是 Step 5 的唯一例外**（交付物只有空清单模板，须汇报"待代码落盘后重跑"），脚本空采集报错文案同步给出该指引
- **【中】输出目录约定与推荐命令不兼容**：SKILL.md 原「新输出统一归到 `03-审查产物/`」与用户已裁定口径（输出 `out/`）冲突，且照该约定用 `-l` 后裸跑 `pack` 会因找不到清单退出 1。现改为「默认 `out/`（用户已裁定）」，并规定**另用目录时必须全程带同一组 `-l`/`-o`**（Step 4 与 Step 5 两处口径统一）
- **【低】清单写出失败裸 traceback**：`cli.py` 原直接调 `listing.write_listing`，`os.makedirs` 抛 `FileExistsError`/`OSError` 时绕过 `CliError`。现捕获并转为 `[错误] 清单写出失败…（请确认输出目录可写，或用 -l 指定其它路径）`
- **【低】Django 示例与 manage.py 例外冲突**：SKILL.md Step 3 入口列表与「常见项目映射示例」的 Django 行原把 `manage.py` 列为入口，与「脚本剔除 manage.py」矛盾（历史遗留）。两处均改为标注其为框架脚手架、不入清单
- **复核未采纳项（经核实不成立）**：复核第 6 条称 V2.0.2 的端到端实测证据不成立（原项目产物时间戳无当天写入）。**该指控有误**——实测刻意跑在 `%TEMP%` 的源码副本上以避免改动用户项目产物（这正是只读保护），故原项目时间戳不变属预期；数字（智能家居 65 条 / 6,085 行）可独立复现
- **回归**：**94 项测试全绿**（V2.0.2 为 86 项，新增 8 项：`DeliveryLineTest` 6 项 + `-q` 交付判定 + `--dry-run` 无交付行）；五项修复逐项实测生效（`-q` 报交付、对账不平报存疑、缺文件报不完整、空项目给指引、写出失败转 CliError）

## V2.0.2（2026-10-13）

**修复「清单生成后未自动生成源代码汇总 md」的流程断点**（棉花项目实测暴露：`out/核心代码名称.md` 已生成，同目录无任何 `源代码-*.md`）

- **根因在 skill 流程而非脚本**：`project-critical/SKILL.md` 原 Step 4 把清单定义为「**唯一产出**」，Step 5 随即自检交付收尾，全程没有任何一步要求产出源代码汇总 md；「配套脚本」一节又标为「V2.0 起，**可选加速**」，导致流程在清单处即告完成
- **SKILL.md 流程重构（Step 4/5/6）**：Step 4 改名「生成核心代码清单」并去掉"唯一产出"表述、新增完成判据（明确"本步完成不等于任务完成"）；**新增 Step 5「生成源代码汇总 md（强制，紧随 Step 4，不得省略）」**，含产出路径、推荐用法、完成判据（`[统计]`/`[输出]` 俱在 + 对账恒等式成立）与「两份材料缺一不可」交付自检；原 Step 5 顺延为 Step 6 并增加双材料复核；frontmatter 的 `description`/`whenToUse` 同步改为「清单 + 源代码汇总 md 一体化生成」，声明"清单落盘后不得收尾"
- **配套脚本一节由「可选加速」改为「必跑」**：明确脚本是 Step 4 + Step 5 的执行体、产出为两份材料、**禁止只跑 `list`**（属流程半成品，需补跑 `pack`），并新增「脚本不可用时的手工兜底」条款——不得因脚本不可用而跳过 Step 5
- **CLI 防呆提示**：`list` 子命令写出清单后新增 `[下一步]` 提示，指明源代码汇总 md 尚未产出、需补跑 `pack` 或改用 `run`；`report.py` 的会话统计新增 `[交付]` 自检行——两份材料齐备时报告各自条目数与行数，缺任一份时明确报出缺失项并指引按 Step 5 补跑（`stat` 不产出文档，不做该自检）
- **回归**：**86 项测试全绿**（新增 2 项：`list` 必提示补跑、`run` 必报两份材料齐备）；真实项目端到端实测——先跑 `list` 复现「仅有清单、无汇总 md」并命中新提示，再跑 `run` 得清单 65 条 + 汇总 6,085 行，`[交付] 两份材料齐备`，对账恒等式成立

## V2.0.1（2026-10-13）

**修复 WPF / MAUI / Avalonia 桌面客户端项目无法采集 `.xaml` 的缺口**（乾图招聘项目实测暴露）

- **采集白名单补 `.xaml`**：`listing.py` 的 `FRONTEND_EXTS` 此前不含 `.xaml`，而 `cli.py` 按 `COLLECT_EXTS` 校验清单条目，把 `.xaml` 判为"类型不在采集范围"跳过，造成「清单 23 条 / 汇编 21 文件」不一致。**注意 `--keep-path` 只在 `--auto-list` 生成清单时生效，绕不过该校验**
- **新增 XAML 根元素嗅探** `is_style_xaml()`：XAML 分两类——根元素为 `ResourceDictionary`（主题 / 图标 / 画笔资源字典）属**样式、剔除**；根元素为 `Window` / `UserControl` / `Page` / `Application` 的是**页面结构程序、保留**（与小程序 `.wxml` 同性质）。嗅探前 4096 字符并跳过 `<?xml?>` 声明与 `<!-- -->` 注释；判不出根元素时**保留**，避免错杀页面
- **语言注册补 `.xaml`**：`languages.py` 的 Markup 组此前已含 `.wxml` / `.axml` / `.html` / `.svg`，唯独漏 `.xaml`；补入后按 `<!-- -->` 注释规则计入四口径统计
- **SKILL.md 同步 7 处**：Step 1 采集扩展名、Step 2 样式条款、Step 2 必须保留、排除清单速查表（样式行改写 + 新增「桌面客户端」行）、常见项目映射示例（新增 WPF / MAUI）、注意事项（新增 `.xaml` 成对入清单条）
- **实测**（乾图招聘流程与人才库管理系统软件）：自动清单纳入 11 个页面 XAML、剔除 `Theme.xaml` / `Icons.xaml` 两个资源字典；`pack` 复核「条目 23 / 命中 23 / 缺失 0 / 违规 0」，汇编 5,713 行、对账恒等式 `md_body_lines = sum_file_phys` 通过；**回归 84 项测试 + 121 subtests 全通过**

## V2.0（2026-10-12）

**形态变化：图形界面 → 无界面命令行**（旧 GUI 程序、打包产物与备份已按用户要求清除，不再保留归档）

- 新入口 `codescrape.py`：在**项目根目录**零参数执行 `python <skill目录>/code-scrape/codescrape.py run`，自动产出清单与汇总文档，不再需要选择文件夹、勾选文件、点击"开始整理"
- 子命令：`run`（清单+汇总）/ `list`（仅清单）/ `pack`（仅汇总）/ `stat`（只统计）/ `scan`（诊断）；项目名默认取目录名中的中文，可用 `--project-name` 校正为登记全称
- **输出文档不再写头部统计**：汇总 md 只含按清单顺序连续拼接的源码正文（无标题、无统计列表、无 `---`），统计改为**生成完成后输出到会话**，`--stats-json` 可落盘；如需旧版头部用 `--keep-header` 临时回退
- **行数统计算法重写**（单遍词法状态机，覆盖 60+ 扩展名 / 30+ 语言），修复四类硬缺陷：① 字符串内的 `/*`、`/**` 被当成块注释开始并**吞掉后续行**（`WebConfig.java` 旧 26 → 新 47）；② `.wxml` 完全不识别 HTML 注释（多算）；③ `.vue` 只认 `<!-- -->`、漏识别 `<script>` 内 JS 注释；④ `.sql` 不认 `--` 行注释。新增嵌套块注释、heredoc、跨行字符串、SFC 分块与未闭合容错
- **四口径统计**：物理行 / 空行 / 注释行 / 有效代码行，恒等式 `物理行 = 空行 + 注释行 + 有效代码行`；口径固定为"多行字符串与 docstring 计注释、混合行计代码、Shebang 与编码声明计注释"
- **统计与产物对账**：`md 正文总行数 = Σ各文件物理行 + 失败占位行 +（可选）文件分隔行`，每次运行自检，不平即报内部错误
- **清单规则同步升级**：剪枝 `tools/`、`scripts/`、`migrations/`、`_legacy/`（防御性剪枝条目，目录本身已清除）；前端不再采集 `.html`；`env.js`/`next-env.d.ts` 等归配置；纯 import/re-export 的 `__init__.py`、`index.ts` 判空包剔除；同名数字变体（`start_server2.py`）剔除；`manage.py` 与 Django `settings.py` 剔除；演示/模拟设施目录（`*_simulator/`、`*_emulator/`、`*_demo/`、`demos/`、`samples/`、`fixtures/`）剔除（**不匹配裸 `demo/`**，避免误杀 `com/demo/` 这类包路径）；新增项目级白名单 `--keep-path`
- **排序双模式**：Spring Boot 型走"全局类别优先"；NestJS 型（`*.controller.*`/`*.service.*` 等后缀 ≥3 个且跨 ≥2 目录）走"业务模块优先"；Next.js 的 `pages/_app.tsx`、`_document.tsx` 纳入入口
- **与历史数字对照**：`--legacy-report` 并列"V1.6 旧算法数字 + 逐条差异归因"（旧算法仅作只读快照 `codescrape/legacy_count.py`，**不参与任何产出**）。实测水电项目 70 文件：旧 3304 / 新 3288，逐行差异 58 条全部归因（`WebConfig.java` +21、12 个 `.wxml` 的 HTML 注释 −37）
- **不打包 exe**（本期不做；CLI 直接以 Python 运行，旧 exe 与 PyInstaller 打包产物已于 V2.0 清理时删除）
- 配置：`settings.json` 保留（CLI 只读，不回写）；旧版脚本目录的 `忽略规则.gitignore` 已删除，忽略规则改为**项目根自备同名文件**或 `--rules` 指定（都不存在则按无规则处理，不创建文件）
